# 장애 보고서: 운영(prod) EC2 인스턴스 전면 응답 불가

- **발생일**: 2026-09-07 (구체 발생 시각 미상, 발견 시각 오전)
- **복구일시**: 2026-09-07 10:31 UTC경 (인스턴스 재부팅 후)
- **영향 범위**: 운영 서버(`15.165.206.173`, `iitsaii-server` / `i-0a21128da1a4e7355`) 전체
  - SSH(22) 접속 불가 (타임아웃)
  - Swagger 문서 등 HTTPS(443) 응답 없음 (무한 로딩/타임아웃)
  - 재부팅 직후 한동안 nginx는 응답하되 애플리케이션이 502 Bad Gateway
- **심각도**: High (운영 서버 전체 접근 불가, API 응답 불가)

## 증상 타임라인

1. SSH(22) 접속 시도 시 `Operation timed out`
2. Swagger 문서(443)도 동일하게 무한 로딩 후 타임아웃 — SSH 전용 문제가 아니라 인스턴스 전체 네트워크 응답 불가로 판단
3. AWS 콘솔 확인 결과:
   - 인스턴스 상태: `running` (정상)
   - 퍼블릭 IP: 변경 없음 (`15.165.206.173` 그대로)
   - **상태 검사(Status Checks): 시스템 상태 검사 통과 / 인스턴스 상태 검사 실패** (1시간 이상 지속)
   - EBS 상태 검사: 통과
4. 인스턴스 재부팅(Reboot) 실행 → 재부팅 직후 nginx는 응답하지만 백엔드가 `502 Bad Gateway`
5. SSH로 직접 접속해 `docker logs photobooth-app` 확인 결과, 재부팅 전 로그에서 다음 예외 반복 확인:
   ```
   java.net.UnknownHostException: iitsaii-db.c3smo0mswz7n.ap-northeast-2.rds.amazonaws.com
   ```
   → RDS 호스트명 DNS 조회 실패로 HikariCP 커넥션 생성 불가 → 앱이 graceful shutdown → 재시작을 반복
6. 재부팅으로 OS 네트워크 스택이 정상화되며 DNS 조회도 복구, 앱이 RDS에 정상 연결되어 기동 성공
7. 최종 확인:
   ```
   curl localhost:8080/swagger-ui/index.html → 200
   curl localhost:8080/v3/api-docs          → 200
   ```
   앱 정상화 확인

## 근본 원인 (Root Cause)

EC2 인스턴스의 **인스턴스 상태 검사(Instance Status Check)만 실패**(시스템/EBS 상태 검사는 정상) — 즉 호스트 하드웨어가 아닌 **인스턴스 OS 레벨 네트워킹 스택 이상**이 발생.

이로 인해:
- 인바운드: SSH(22), HTTPS(443) 등 모든 포트에 대한 응답 불가
- 아웃바운드: DNS 조회 자체가 실패 (RDS 엔드포인트 이름 해석 불가)

애플리케이션/DB/보안그룹/코드 설정 문제가 아니라, **인스턴스 OS 네트워크 스택의 일시적 장애**로 판단됨. 정확한 트리거(커널 이슈, 리소스 고갈 등)는 로그상으로는 특정하지 못함.

## 진단 과정에서 배제한 가설

- ~~보안그룹 인바운드 IP 허용 목록이 SSH 접속 IP 변경으로 stale해진 것~~ → Swagger(443)도 동일하게 막혀있어 SSH 전용 문제가 아님을 확인, 배제
- ~~인스턴스 재시작으로 퍼블릭 IP가 바뀐 것~~ → AWS 콘솔에서 IP 불변 확인, 배제

## 조치 (Resolution)

- EC2 콘솔에서 **인스턴스 재부팅(Reboot)** 실행 (Stop/Start가 아닌 Reboot이므로 퍼블릭 IP 유지됨)
- 재부팅 후 OS 네트워크 스택 정상화 → DNS 조회 복구 → `photobooth-app` 컨테이너가 RDS에 정상 연결되어 기동
- 컨테이너 자체는 `restart` 정책에 의해 별도 조치 없이 자동 재기동됨
